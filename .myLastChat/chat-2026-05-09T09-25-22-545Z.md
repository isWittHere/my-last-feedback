## 核心结论

它的设计关键不是“播放一个 loading 动画”，而是把 Agent 输出过程拆成多个语义状态，并让每个状态绑定不同的像素阵列动画形态：

- thinking：流体融合动画 `metaballs`
- output：输出态随机使用 `tetris` 或 `matrix_rain`
- tool_call：工具调用态随机使用 `kaleidoscope`、`morph`、`ripple`
- settle：流式结束后播放一次非循环结算动画，随机使用 `scanLoading` 或 `centerLoading`

## 状态检测方式

`StreamingIndicator.tsx` 通过最近一条 assistant message 的最后一个 block 类型判断当前流式阶段：

- 最后 block 是 `thinking` → thinking
- 最后 block 是 `tool_call` → tool_call
- 其他情况 → output
- 没有 assistant block → thinking

这意味着动画不是由外部手动塞一个状态枚举，而是从消息结构自然推导出来。

## 动画执行模型

`DotMatrix.tsx` 是一个通用 7×7 点阵播放器：

- 每一帧是 `number[][]`，尺寸固定为 7×7。
- 每个格子的值是亮度等级：`0` 透明，`1-4` 对应 CSS 变量 `--dot-lv1` 到 `--dot-lv4`。
- 动画 preset 是 generator：`gen(): Generator<number[][]>`。
- 播放器用 `setTimeout` 按 preset interval 推进帧。
- loop 模式结束后重新创建 generator。
- 非 loop 模式结束后触发 `onComplete`。

## 为什么它看起来不像普通 spinner

它有三层设计：

1. 形态差异：不同状态使用完全不同的视觉语法，不只是速度或颜色不同。
2. 状态稳定随机：同一轮 stream + 同一 phase 会固定一个随机动画，避免每次 render 抖动；新一轮 stream 才重新随机。
3. 结束过渡：流式停止后不会立刻消失，而是进入 settle 模式播放一次扫描/扩散动画，然后隐藏。

## 对我们项目的启发

如果要迁移到 MLFB，比较适合把它抽象成一个小型 `AgentActivityMatrix`：

- 从 Agent 当前 step 类型推导 phase。
- thinking step 显示流体/呼吸式点阵。
- tool step 显示形变/涟漪/衍射类点阵。
- assistant output 显示矩阵雨/块落下类点阵。
- stream 结束时播放一次收束动画。
- 保持 7×7 小尺寸，不抢聊天正文注意力。
