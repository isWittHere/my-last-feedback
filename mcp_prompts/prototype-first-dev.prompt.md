## 原型先行开发方法论 (Prototype-First Development)

当面对**复杂、不确定或涉及视觉/交互**的功能需求时，遵循以下 5 阶段流程：

### Phase 1: 方案分析 (Analyze)

- 深入分析问题本质，理解技术约束
- 提出 2~4 个可行方案，列出各方案优缺点
- 与用户讨论确认最终方案
- **产出**: 方案对比表 + 用户确认

### Phase 2: 独立原型 (Prototype)

- 创建**完全独立**的可运行 demo 文件，脱离主代码库
- 推荐格式:
  - 前端功能 → 单文件 HTML（含内联 JS/CSS），可直接浏览器打开
  - 后端算法 → 独立 Python 脚本，可直接 `python script.py` 运行
  - API 设计 → 最小 FastAPI 应用
- 存放位置: `.myLastChat/` 目录（不污染主代码）
- **关键原则**: demo 必须能独立运行，不依赖主项目的任何模块

### Phase 3: 快速迭代 (Iterate)

- 在 demo 上快速迭代，每次改动后让用户验证效果
- 使用 interactive_feedback 工具收集用户反馈
- 逐步完善直到用户满意
- **节奏**: 小步快跑，每轮迭代只改一个方面

### Phase 4: 规划文档 (Plan)

- 在 demo 验证通过后，输出正式的实现规划文档
- 文档格式遵循 MyLastChat 规范（YAML frontmatter + Markdown）
- 内容包括: 改动清单、影响分析、实现步骤、回滚方案
- 存放: `.myLastChat/MLC_[功能名]规划书.md`

### Phase 5: 正式实现 (Implement)

- 将 demo 中验证过的逻辑移植到主代码库
- 按规划文档分步实施，每步完成后验证
- 保留 demo 文件作为功能参考和回归测试基准

## 适用场景

| 适用 | 不适用 |
|------|--------|
| UI/UX 新功能（图表、动画、交互） | 简单 Bug 修复 |
| 算法设计与验证 | 配置变更 |
| 流式/实时数据处理管线 | 已有明确实现方式的改动 |
| 不确定最终效果的新功能 | 纯重构（无行为变更） |
| 涉及多组件协调的架构改动 | 文档更新 |

## Demo 文件规范

- **命名**: 功能描述性名称，如 `chart_streaming_demo.html`、`sankey_layout_test.py`
- **自包含**: 所有依赖通过 CDN 引入（前端）或标准库实现（后端）
- **可交互**: 提供按钮/控件让用户操作和验证
- **有对比**: 尽量展示优化前后的效果差异
