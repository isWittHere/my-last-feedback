# 如何提交规划方案草案

## 工具

```text
expert_submit(type="plan_draft", content=<规划书>, progress?=...)
```

- 调用后会 **阻塞**，直到下一条指令（通常是审查反馈）到达
- 可多轮迭代，直到通过投票

## 准备工作

1. 读取 `AGENTS.md` 了解项目架构、技术栈、规范
2. 打开与任务直接相关的核心代码文件确认现状
3. 识别用户任务的显式要求和隐式约束

## 规划书模板

```markdown
# 规划方案: {任务标题}

## 需求分析
- 需求要点 1: {描述}
- 需求要点 2: {描述}

## 技术调研
- 当前架构: {相关模块的现状}
- 技术选型: {如有新技术引入}
- 影响范围: {哪些模块会被影响}

## 执行计划

### Phase 1: {阶段名称}
- **目标**: {本阶段要达成什么}
- **涉及文件**:
  - `path/to/file.ts` — {修改内容概述}
- **验收标准**:
  - [ ] {具体可验证的标准 1}
  - [ ] {具体可验证的标准 2}
- **依赖**: 无 / Phase N

### Phase 2: {阶段名称}
...

## 风险评估
- 风险 1: {描述} — 应对策略: {措施}

## 注意事项
- {需要特别注意的点}
```

## 迭代纪律

收到审查反馈后：

1. 按 `skill_decision_levels` 区分每条反馈的级别
2. 必须修复项必须处理；建议改进项若不采纳需写明理由
3. 针对性修改，不要推翻全案
4. 再次 `expert_submit` 前先做自检（内容一致性、验收标准是否可验证）

## 提交前自检清单

- [ ] 上一轮所有「必须修复」项已处理
- [ ] 未采纳的「建议改进」项已准备好理由
- [ ] 每个 Phase 有明确目标、涉及文件、验收标准
- [ ] 验收标准是具体、可验证的
- [ ] 未出现委派表述（参考 `skill_hallucination_check`）
